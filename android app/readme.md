# BMS Monitor 🔋 (Android)

> Сучасний, легкий та нативний Android-застосунок на **Jetpack Compose (Material 3)** для оперативного моніторингу та перегляду історичної аналітики акумуляторних збірок із платами керування **JK-BMS** (через ESP32-шлюзи), інтегрований із власною хмарою **Micro IoT Cloud** або локальними HTTP-ендпоінтами.

## 📌 Головні можливості

- **⚡ Ультракомпактний моніторинг у реальному часі:**
  - Загальна зведена картка акумуляторної збірки (**Pack Overview**): загальна напруга, сумарний струм, потужність (W / kW), залишок ємності (Ah) та середній рівень заряду (SOC).
  - Горизонтальний компактний статус-бар рівня заряду (SOC) в один рядок із відсотками.
  - Динамічні індивідуальні картки для кожного модуля BMS (1..N пристроїв у збірці).
  - Відображення балансування комірок: розбіг дельти напруги в мілівольтах ($\Delta$ mV) з кольоровим кодуванням норми/уваги, кількість послідовних комірок ($S$), температура (датчики T1, T2, MOS-транзистори), лічильник циклів та активні тривоги/аварії (Alarms).
  - Підтримка з'єднання модулів: **паралельне** (середнє арифметичне V) та **послідовне** (сума V).
  - Гнучке налаштування полярності струму (струм $> 0$ як заряд або розряд).

- **🏢 Мультипрофілі та об'єкти (Multi-Site Profiles):**
  - Миттєве перемикання між різними локаціями через нижню шторку (**Bottom Sheet**): `🏠 Дім`, `🏢 Робота`, `👨‍👩‍👧 Батьки`, `🚗 Гараж`.
  - Повна ізоляція налаштувань для кожного об'єкта (власна адреса сервера, токен користувача, фільтр `device_id`, тип з'єднання, назва збірки тощо).
  - **Нульове навантаження у фоні:** опитування виконується виключно для активного об'єкта і лише коли застосунок відкрито на екрані.

- **📈 Власний Canvas-графік історії (v1.2):**
  - Отримання та построковий парсинг архівів **NDJSON** із Micro Cloud (`backend/history.php`).
  - **Два режими відображення:**
    1. *«Один BMS — усі параметри»*: одночасний вивід 5 кривих (Напруга, Струм, SOC, Потужність, Залишок Ah), де кожна крива має незалежне автомасштабування min..max із відступом 8%.
    2. *«Усі BMS — один параметр»*: спільна шкала з числовими підписами осі для зручного порівняння розбіжностей модулів між собою.
  - **Фільтр офлайн-даних:** точки з `connected == false` або `battery_voltage == 0` автоматично відсікаються, щоб не порушувати масштаби.
  - **Інтелектуальні розриви ліній:** автоматичний розрив шляху графіка, якщо проміжок між точками перевищує 2.5 кроку запису.
  - **Інтерактивний курсор:** перетягування або тап установлює точний маркер із відображенням мітки часу, значень та бейджів, що автоматично розсуваються для уникнення перекриття.
  - **Офлайн-кешування:** останній завантажений архів зберігається у файл, що дозволяє переглядати історію навіть за відсутності зв'язку.
  - Повна підтримка альбомної (Landscape) орієнтації.

- **🔍 JSON Інспектор:**
  - Вбудований інструмент діагностики для перевірки сирого вихлопу хмари чи ESP32, ручного тестування та налагодження структури даних.

## 🛠️ Архітектура та стек технологій

- **Мова:** Kotlin 2.0+
- **UI:** Jetpack Compose (Material Design 3)
- **Архітектурний патерн:** MVVM (Model-View-ViewModel) + Clean Architecture
- **Асинхронність:** Kotlin Coroutines & StateFlow
- **Мережа:** OkHttp 4 (з низькими таймаутами та оптимізацією з'єднань)
- **Парсинг:** Нативний високошвидкісний `org.json` без потреби у важких процесорах анотацій (KSP) чи кодогенерації.
- **Графіка:** 100% чистий Jetpack Compose `Canvas` (без сторонніх бібліотек, із прямою оптимізацією під 60/120 fps).

## 📡 Інтеграція з Micro IoT Cloud

Застосунок розроблено для прямої взаємодії з бекендом [Micro IoT Cloud](https://github.com/lagidnyj):

### 1. Поточний стан (Current Telemetry)
* **Запит:**
  ```http
  GET /backend/read.php?api_token=<USER_READ_TOKEN> HTTP/1.1
  Host: your-cloud-domain.com
  ```
* За наявності фільтра по `device_id` у налаштуваннях профілю застосунок автоматично відфільтровує JSON потрібного шлюзу (наприклад, `jk_bms_esp32`), навіть якщо на акаунті зареєстровано погодні станції чи інші прилади.
* Часові мітки автоматично приводяться з UTC до локального часу смартфона.

### 2. Історичний архів (NDJSON History)
* **Запит:**
  ```http
  GET /backend/history.php?api_token=<USER_READ_TOKEN>&device=<DEVICE_ID> HTTP/1.1
  Host: your-cloud-domain.com
  ```
* **Формат відповіді:** один JSON на рядок (NDJSON):
  ```json
  {"timestamp":"2026-11-05T21:14:38Z","slot":"2026-11-05T21:00:00Z","interval_seconds":3600,"state":{"c8:47:80:22:0f:e0":{"battery_voltage":54.24,"charge_current":1.2,"battery_power":65,"percent_remain":99,"capacity_remain":228.5,"connected":true}}}
  ```

## ⚙️ Налаштування та конфігурація

У меню **Налаштування** (іконка шестірні) доступні наступні параметри для активного профілю:

1. **Джерело даних:**
   - **Micro Cloud (API v1):** Адреса сервера (`https://...`), токен читання користувача та опціональний ID пристрою (`cloudDeviceId`).
   - **Прямий HTTP / Локальний IP:** Наприклад, `http://192.168.4.1/status.json` при підключенні напряму до точки доступу ESP32.
   - **Демо-режим:** Повна емуляція 3 модулів BMS та 3-денної історії для тестування без апаратної частини.
2. **Конфігурація батареї:**
   - Назва об'єкта / збірки (Pack Title).
   - Тип підключення: Паралельне (середнє V) або Послідовне (сума V).
   - Полярність струму ($>0$ заряд / розряд).
3. **Періоди опитування:**
   - Інтервал оновлення: `10 сек`, `30 сек`, `1 хв`, `5 хв`.
   - Таймаут переходу в Offline: `10 хв`, `30 хв`, `1 год`.
   - Визначення статусу Offline за апаратною часовою міткою `ts`.
   - Пріоритет заголовків карток (`Ім'я`, `ID модуля`, `MAC-адреса`).

## 🚀 Як зібрати проект власноруч

### Вимоги
- **Android Studio** Ladybug (2024.2+) або новіша
- **JDK:** 17 або 21
- **Android SDK:** Compile SDK 36, Min SDK 24 (Android 7.0+)

### Збірка з командного рядка
```bash
# Клонувати репозиторій
git clone https://github.com/lagidnyj/bms-monitor-android.git
cd bms-monitor-android

# Збірка Debug APK
./gradlew assembleDebug

# Запуск модульних тестів
./gradlew testDebugUnitTest
```
Зібраний файл APK буде розміщено за шляхом: `app/build/outputs/apk/debug/app-debug.apk`.
